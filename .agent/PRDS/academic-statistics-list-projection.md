# Academic Analytics：通过率列表预聚合投影

**Priority:** High  
**Status:** Implemented  
**Type:** Enhancement  
**Created:** 2026-09-07  
**Last Updated:** 2026-09-07

## 背景

当前课程通过率列表在每次读取时，对当前发布批次的学期统计记录执行分组、求和、排序，并为总数重复执行一次相同聚合。生产当前批次约有 29,566 条学期记录和 7,375 门课程；并发翻页时会重复产生临时表和 filesort，导致 Analytics MySQL CPU 饱和。

## 目标

1. 在批次发布事务内预生成课程总通过率投影。
2. 将符合最小样本量条件的课程总数持久化，列表读取不再执行 `COUNT(GROUP BY ...)`。
3. 让默认排序和精确筛选走索引；课程号关键词使用前缀匹配，课程名检索只扫描体量较小的投影表。
4. 保持现有公开 API 字段、分页语义、最小样本量隐私门槛与“仅最新已发布批次可见”的一致性。

## 非目标

- 不改变成绩原始数据、统计规则或最小样本量。
- 不删除已有已发布批次；它们是不可变审计记录和趋势数据来源。
- 本次不改教师通过率列表；其投影模型与课程列表类似，但需单独评估体量和排序维度。

## 方案

### 数据模型

- 新增批次级课程总通过率投影表：每行对应 `batch_id + education_level + course_code`。
- 保存列表所需的全部汇总计数、课程名和分布字段；其中直接持久化并展示：样本数 `valid_count`、统计学期数 `term_count`、通过数/不通过数、数值成绩总和与数量。列表响应由这些列直接计算或映射均分与通过率，不再扫描学期表。投影保留小样本行，以便日后调整阈值时不丢失筛选能力；读取时仍执行最小样本量过滤。
- 为 `(batch_id, valid_count DESC, course_code ASC)` 建索引，用于默认排序分页；为 `(batch_id, course_code)` 建索引用于精确和前缀检索。
- 在统计批次表增加公开课程总数，发布时与投影同行写入。

### 发布与读取

1. 原始学期统计写入后，在同一个发布事务内按课程聚合并批量写入投影。
2. 投影、公开课程数和批次 `published` 状态一起提交；事务失败时完整回滚，读者继续看到上一发布批次。
3. 未指定学期时，`ListCourses` 直接查询投影表；无筛选且阈值与发布时一致时读取批次已存总数。筛选列表只对投影表执行普通 `COUNT(*)`，不再对学期表运行时分组。按学期筛选保留原聚合路径，保证现有语义不变。
4. 课程号关键词改为前缀匹配；课程名称维持模糊匹配，但仅在约数千行的投影表上执行。

### 历史批次处理

- 失败批次不会写入统计行或投影（发布使用单一事务），只留下少量批次元数据，不是性能和空间问题。
- 已发布批次不得删除，保留用于趋势、审计和隐私基线。
- 迁移会回填已发布批次的投影，部署后即可查询当前可见批次。旧批次没有记录当时的最小样本量，暂不使用其缓存总数；下一次成功发布后会写入该总数。
- 如需后续清理长期失败批次，应另设保留期、归档和管理员审计任务，不能直接删除。

## 文件范围

- `internal/modules/academic_statistics/domain/`：新增投影实体和批次公开总数字段。
- `internal/modules/academic_statistics/infrastructure/store.go`：发布时写投影；列表改为投影查询。
- `internal/modules/academic_statistics/infrastructure/*_test.go`：覆盖原子发布、排序、总数、筛选与回滚。
- `migrations/`：新增投影表、索引和批次字段。
- `proto/`：仅当需显式声明受限搜索语义时才更新说明，不改响应字段。

## 验收与验证

- 新发布批次的课程列表不读取 `academic_course_term_statistics`。
- 默认无筛选列表只执行一次索引分页查询，不执行聚合或总数查询；筛选列表只执行投影表的普通计数与分页查询。
- 默认排序保持 `valid_count DESC, course_code ASC`。
- 均分、样本数、统计学期数、通过率与当前列表响应一致。
- 最小样本量边界和课程趋势结果不变。
- 并发翻页不再产生聚合临时表；通过 MySQL 执行计划确认不含 `Using temporary` / `Using filesort`。
- 运行 `go test ./...`、`go test -race ./...`（环境允许时）和 `go vet ./...`。
